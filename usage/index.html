はじめての Launchs

GitHub リポジトリからアプリをデプロイ・管理するサービス Launchs の使い方を、 スクリーンショット付きでステップごとに解説します。

🚀 GitHub 連携 📦 コンテナ管理 🌐 インターネット公開 📝 ビルドログ
★

Launchs とは

サービスの概要

Launchs は、GitHub リポジトリに push されたコードを数クリックで本番環境にデプロイできる クラウドプラットフォームです。インフラの知識がなくても、アプリの起動・公開・管理がブラウザ上で完結します。

アプリは 「プロジェクト」 という単位で管理されます。プロジェクトの中に 「コンテナ」 を追加すると、GitHub からコードが自動取得されてビルド・起動されます。 複数のコンテナを同じプロジェクトにまとめることで、フロントエンド・バックエンド・DB を一元管理できます。

📁

プロジェクト

アプリをまとめる単位。複数コンテナをひとつのプロジェクトで管理。

📦

コンテナ

GitHub リポジトリと紐づいたデプロイ単位。Railpackを用いて自動ビルド。

🌐

Ingress

コンテナに外部 URL を発行。HTTPS で即座にアプリを公開できる。

📋

ビルドログ

ビルド・実行のログをリアルタイムで確認。エラーの原因を素早く特定。

💡
ポイント Launchs はリポジトリ指定ディレクトリをrailpackを用いて自動ビルドします。
1

プロジェクトを作成する

アプリを管理するプロジェクトを用意します

Launchs にログイン後、最初は空のプロジェクト一覧が表示されます。 右上の 「+ 新規プロジェクト」 ボタンからプロジェクトを作成しましょう。

  1. 画面右上の 「+ 新規プロジェクト」 ボタンをクリックする
  2. ダイアログが開いたら、プロジェクト名 を入力する
  3. 「プロジェクトを作成」 ボタンをクリックして確定する
  4. 一覧にカードが追加され、ステータスが 「稼働中」 になるのを確認する
  5. カードをクリックしてプロジェクト詳細に移動する
プロジェクト一覧（空の状態）
まだプロジェクトがない初期状態。右上の「+ 新規プロジェクト」から開始します。
プロジェクト作成ダイアログ
プロジェクト名を入力して「プロジェクトを作成」をクリックします。
プロジェクト一覧（カードあり）
「稼働中」バッジが表示されたらカードをクリックして詳細へ進みます。
✅
完了の目安 カードに「稼働中」のバッジが表示されれば、プロジェクトの作成は完了です。 続けてコンテナを追加しましょう。
2

コンテナを追加する（アプリをデプロイする）

GitHub リポジトリを指定してデプロイを開始します

プロジェクト詳細画面でコンテナを追加します。コンテナとは、GitHub リポジトリと紐づいた デプロイの単位です。GitHub URL・ブランチ・ディレクトリ を指定するだけで 自動的にビルドが始まります。

  1. プロジェクト詳細画面の 「+ コンテナを追加」 ボタンをクリックする
  2. コンテナ名 を入力する（例：go-sample-app）
  3. GitHub リポジトリ URL を入力する（例：https://github.com/launchs-org/sample-go-app）
  4. デプロイしたい ブランチ名 を入力する（例：main）
  5. Dockerfile がある ディレクトリ を指定する（ルートの場合は .）
  6. 「デプロイを開始する」 ボタンをクリックする
プロジェクト詳細（コンテナなし）
「+ コンテナを追加」ボタンからデプロイダイアログを開きます。
新規デプロイダイアログ
コンテナ名・GitHub URL・ブランチ・ディレクトリを入力して「デプロイを開始する」をクリック。
⚠️
注意 指定したブランチのルートまたはサブディレクトリに Dockerfile が存在しないとビルドに失敗します。 あらかじめリポジトリに Dockerfile をコミットしておいてください。
3

ビルドの進行を確認する

フロー図とビルドログでビルド状況を追跡します

「デプロイを開始する」をクリックすると、プロジェクト詳細のフロー図に新しいコンテナカードが出現し、 「ビルド中」 バッジが表示されます。ビルドには数秒〜数分かかります。

サイドパネルの 「ビルド」タブ を開くと、ビルドログがリアルタイムで流れてきます。 エラーが発生した場合はここで原因を確認できます。

  1. フロー図にコンテナカードが追加され 「ビルド中」 バッジが表示されるのを確認する
  2. コンテナカードをクリックして右サイドパネルを開く
  3. 「ビルド」タブ を選択してビルドログを確認する
  4. ログの末尾に ビルド成功 のような成功メッセージが出れば完了
ビルド中の画面（フロー図 + ビルド中バッジ）
フロー図にカードが出てビルド中バッジが表示されます。
ビルドログ画面
サイドパネルの「ビルド」タブでリアルタイムのビルドログを確認できます。
🔴
ビルドが失敗したら ビルドログにエラーメッセージが表示されます。 「依存パッケージのインストール失敗」「ポート番号の記述漏れ」です。ログを参考にコードを修正して再デプロイしてください。
4

アプリの起動を確認する

「実行中」ステータスと実行ログで動作を確認します

ビルドが成功するとコンテナが自動的に起動し、フロー図のカードが 「実行中」 に変わります。 サイドパネルの 「実行」タブ ではアプリのリアルタイムログを確認できます。

  1. フロー図のカードのバッジが 「実行中」 に変わるのを確認する
  2. サイドパネルで 「実行」タブ を選択する
  3. アプリのログ出力が流れていることを確認する（例：Listening on port 1323）
実行中の画面（実行タブ・ログ表示）
カードが「実行中」になり、実行タブでアプリのログを確認できます。
🟢
実行中になったら アプリが正常に起動しています。次のステップでインターネットに公開する URL を取得しましょう。
5

アプリをインターネットに公開する

Ingress 設定で外部 URL を発行します

デフォルトではコンテナはサービスを用いた内部ネットワーク内のみでアクセス可能です。 「ネット」タブ の Ingress 設定を有効にすると、HTTPS の外部 URLが発行され、 インターネットからアクセスできるようになります。

  1. サイドパネルで 「ネット」タブ を選択する
  2. 内部ポート設定 にアプリが LISTEN しているポート番号を入力する（例：1323）
  3. 外部公開 のトグルをオンにする
  4. 数秒後に DEFAULT DOMAIN の URL が発行される
  5. 発行された URL をブラウザで開き、アプリが表示されることを確認する
ネットタブ（Ingress設定・DEFAULT DOMAIN発行済み）
外部公開を有効にすると DEFAULT DOMAIN の URL が発行されます。
💡
ポイント 発行された DEFAULT DOMAIN は https:// の HTTPS 接続です。 独自ドメインを割り当てたい場合はカスタムドメイン設定を利用してください。
⚠️
注意 アプリが指定したポートで LISTEN していない場合、URL を開いてもエラーになります。 実行ログで Listening on port <number> のようなメッセージを確認し、 内部ポート設定と一致しているか確かめてください。
6

コンテナを削除する

不要になったコンテナを安全に削除します

不要になったコンテナは 「削除」タブ から削除できます。 誤削除を防ぐため、コンテナ名を入力しないと削除ボタンが有効になりません。

  1. 削除したいコンテナカードをクリックしてサイドパネルを開く
  2. 「削除」タブ を選択する
  3. 確認欄に コンテナ名 を正確に入力する
  4. 削除ボタンが有効化されたら 「削除する」 をクリックする
削除タブ
コンテナ名を入力して削除ボタンが有効になったら削除を実行します。
⛔
注意：この操作は取り消せません コンテナを削除すると、そのコンテナのビルドキャッシュ・実行ログ・Ingress 設定がすべて失われます。 データを別途バックアップしてから削除してください。
7

プロジェクトを削除する

不要になったプロジェクトをまとめて削除します

プロジェクトが不要になった場合は、プロジェクト一覧から削除できます。 プロジェクトを削除するには、先に 中のコンテナをすべて削除 しておく必要があります。

  1. 左メニューの 「プロジェクト」 をクリックしてプロジェクト一覧に移動する
  2. 削除したいプロジェクトのカードに マウスを乗せる
  3. 右上に表示される 「…」ボタン をクリックする
  4. メニューから 「プロジェクトを削除」 を選択する
  5. 確認ダイアログが表示されるので 「OK」 をクリックして確定する
プロジェクト削除メニュー
カードにマウスを乗せると「…」ボタンが現れ、「プロジェクトを削除」が選択できます。
⚠️
削除前にコンテナを削除してください プロジェクト内にコンテナが残っている状態でも削除操作は可能ですが、中のコンテナや関連リソースもすべて一緒に削除されます。 大切なデータがある場合は事前にバックアップしてください。
⛔
注意：この操作は取り消せません プロジェクトを削除すると、プロジェクト内のすべてのコンテナ・ビルド履歴・ログ・設定が完全に削除されます。 復元する手段はありませんので、十分に確認してから実行してください。
